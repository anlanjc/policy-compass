## 3. 结论：mock 判分口径下向量腿增益是否复现？

1. **哈希向量腿不构成"增益"证据，复现问题本身被拆解**：S1 的 mock e2e +2.2/+3.0pp 是"真向量混合腿 vs 哈希向量腿"的差，不是"有无向量腿"的差——哈希词袋向量非语义向量，其排序贡献与 BM25 高度重叠且带噪声。quirk 修复后实测：检索层 hybrid_full(哈希) 比生产 BM25 **拖低** recall@5（v1 -5.7pp / v2 -2.8pp）；e2e 双臂 ±2~3 题、方向相反（v1 +3.0 / v2 -2.2）——落在 mock 判分噪声量级，**不构成可复现的稳定增益**。
2. **"生产要不要开向量腿"的最终判断不变**：真向量（text-embedding-v4）口径的检索增益与真模型复验反向证据均为 S1 旧输入口径的历史结论（本次真修复改变全部向量输入 → 那批数字严格说需重嵌复验后才可引用为现行证据）；**本轮零现金可升级的只有 mock 口径**——升级后的 mock 证据反而进一步支持"维持 BM25-only 默认"：连 mock 判分器自己都测不出哈希向量腿的稳定 e2e 增益，真向量增益在 mock 与 real 两层都待现金窗口复验。
3. **CI 门禁语义**：门禁守护"相对基线无回归"（B 口径自洽），本报告不改变该语义；但基线快照锚在 quirk 修复前哈希向量上，**门禁基线重建为遗留项**（逐条判读"重建≠放水"纪律见 ablation.md §3/§7）。

## 4. 诚实边界与现金窗口

- **真向量未复跑**：修复后输入口径（`标题\n《标题》\n正文`）下的 text-embedding-v4 重嵌（68 chunk，S1 实测 ≈3.1 万字符 ≤¥0.05）与 hybrid 真向量五组+真模型 e2e 复验（S1 实测 ≈¥1~4）**均未执行**——零现金红线；S1 表格（ablation.md §1/§4）保留为旧输入口径历史证据，不再回填新数字。
- **mock 判分脆性**：e2e 失败集逐条归因均为 mock 抽取式判分脆性（检索召回正确；#138 等，见 EVIDENCE 1B4 节与 fail_analysis.md）——mock e2e 是链路回归裁判，不是增益外推依据（S1 §4 教训在本轮复现中再次成立）。
- **单次采样**：mock 链路确定性（md5 纯函数+确定性抽取生成器），单次即逐字可复现；但 n=78/29 小样本，±1~2 题差异不作结论。
- v1 e2e 生产 BM25 臂 84.9%（#1/6/22/27/28）与旧冻结 B 口径 84.9% **同值不同径**（旧=哈希向量腿开，新=向量关）——n=33 下不同配置落到同一失败集属巧合，已逐格核对失败 id 一致后才作记录（同 S1"93.3% 同值属巧合"的诚实口径）。
