# L3 · OCR 与元数据兜底精读：让扫描件红头公文变成可检索语料

> 精读对象：`app/ingestion/loader.py`（约 48 行）+ `app/ingestion/ocr.py`（约 101 行）+ `app/ingestion/metadata.py`（约 118 行）。
> 配套测试：`tests/test_retrieval.py:57-92`（元数据两条用例：规范头文档 + 脏文本兜底）。
> 踩坑背景（PROJECT_BOOK 踩坑实录第 6 条）：4 页红头文件 pypdf 仅得 3 字符 → 视觉 OCR 管线 + 哈希缓存 → 真实政策全链路接入。

---

## 0. 问题定义

真实政务语料的两个现实：

1. **形态现实**：相当比例是红头文件**扫描件**，pypdf 抽出文本近于零（loader.py:3-5："实测某 4 页红头文件仅 3 字符"）；
2. **元数据现实**：干净语料有 `【发文字号】` 元数据头，OCR 转录的真实公文**没有**——而检索层的城市/领域/时效加权（L1 §4）全靠元数据工作。

两条管线分别解决：**两级 PDF 解析**（文本 → 视觉 OCR）+ **两级元数据抽取**（规范头 → 正文兜底）。

---

## 1. 两级 PDF 解析（loader.py + ocr.py）

### 1.1 扫描件判定：文本密度阈值（ocr.py:29-37）

```python
TEXT_DENSITY_THRESHOLD = 30   # 每页抽取字符数低于该阈值判定为扫描件

def is_scanned_pdf(text: str, pages: int) -> bool:
    if pages == 0:
        return False
    return len(text.strip()) / pages < TEXT_DENSITY_THRESHOLD
```

用**页均字符密度**而不是总字符数——10 页里混 1 页图片页不算扫描件，整本扫描才触发。`pages == 0` 先排除（防除零，空 PDF 不该误判为扫描件）。30 字符/页的依据：正文页正常应远高于此（ocr.py:29 注释）。

### 1.2 load_file 的降级链（loader.py:15-36）

```
.md/.txt → 直接读
.pdf     → pypdf 逐页 extract_text
            → is_scanned_pdf? 否 → 返回文本
                        是 → llm is None? 抛 ValueError（明确报错）
                            → ocr_pdf(llm, path)
                            → OCR 结果为空也抛 ValueError（loader.py:33-34）
```

注意两处**显式抛错**而不是静默返回空串：扫描件无法解析时要让上层跳过该文档并记录（ocr.py:7-8 的调用约定），空文本进索引是静默污染。

### 1.3 OCR 管线（ocr.py:40-100）

三段：

1. **渲染**（render_pages，ocr.py:40-50）：pymupdf 逐页 `get_pixmap(dpi=150)` 转 PNG 字节——150 dpi 是"视觉模型可读+体积可控"的平衡；
2. **逐页转录**（ocr_pdf，ocr.py:53-95）：每页一次视觉模型调用（OpenAI-compatible vision 格式，image_url + OCR_PROMPT），`temperature=0.0`（转录任务不要创造性）；`max_pages=10` 封顶；**单页失败只 warn 跳过**（ocr.py:95-96），一页 OCR 挂了不该废掉整份文档；
3. **缓存**（ocr.py:61-68）：`sha256(文件字节)[:16]` 作 key，`{stem}_{hash}.txt` 存 `data/ocr_cache/`。**为什么按内容哈希而不是文件名**：同路径文件被替换后哈希变化自然失效；重复摄取/重建索引/离线测试全部复用——OCR 昂贵（每页一次视觉模型调用），docstring（ocr.py:55-58）明说这是为重复摄取与 CI 设计的。

**mock 模式的诚实失败**（ocr.py:69-72）：缓存未命中且 `effective_llm_mode == "mock"` 时抛 ValueError（"提交 data/ocr_cache 可离线测试"）——mock 没有视觉能力，宁可让该文档缺席并留痕，也不让管线假装成功。

OCR_PROMPT（ocr.py:22-27）三条指令值得注意：红头标题、**发文字号（如 杭房公委〔2025〕4号）**、落款日期全部转录；保留条款结构；只输出纯文本。第一条直接为 §2 的文号抽取供给原料——OCR 的 prompt 是按下游元数据抽取的需求反推的。

## 2. 两级元数据抽取（metadata.py）

### 2.1 数据契约 PolicyMeta（metadata.py:19-33）

七个字段：doc_id / file_name / title / **doc_no（发文字号）** / **effective_date（生效日期）** / **status（现行有效/已废止）** / city / domain / file_hash。`is_valid` 是 property：`"废止" not in status`（metadata.py:31-33）——它是 L1 加权里 `invalid_doc_penalty ×0.3` 的信号源。

为什么元数据在**摄取期**一次性抽取（模块 docstring metadata.py:6-8）：检索期每次查询都抽一遍是浪费；且"规则能锁死的绝不交给模型"——城市/领域/文号用正则，抽错是确定性的、可修的。

### 2.2 第一级：规范头解析（extract_metadata 主体，metadata.py:85-108）

```
【发文字号】杭公积金委〔2022〕11号
【生效日期】2022-01-01
【状态】已废止（2025年7月1日起废止）
【适用城市】杭州
【领域】公积金
```

逐行 `_META_PATTERNS` 匹配（metadata.py:36-42, 96-99），标题取 `# ` 行。测试锚点 tests/test_retrieval.py:57-71：全字段断言 + `not meta.is_valid` + file_hash 长度 64。

### 2.3 第二级：脏文档正文兜底（_fallback_extract，metadata.py:44-82）

触发条件（metadata.py:100-101）：`not content.startswith("【")`——正文不以元数据头开头即视为脏文档（OCR 转录文本的典型形态）。四条兜底正则/规则：

| 目标 | 实现 | 细节 |
|---|---|---|
| 文号 | `_DIRTY_DOC_NO = re.compile(r"[\u4e00-\u9fff]{2,12}〔\d{4}〕\d+号")`（metadata.py:45） | 匹配"杭房公委〔2023〕8号"这类机构名+全角括号年份+序号——〔〕是公文专用括号，几乎不误伤 |
| 施行日期 | `_DIRTY_EFFECTIVE = re.compile(r"[自](\d{4})年(\d{1,2})月(\d{1,2})日起?(?:实施\|施行)")`（metadata.py:47） | **两种公文写法都接受**："自2024年1月1日起实施"与"…起施行"（源码注释 metadata.py:46："实测真实文件两种都在用"）；格式化为 `%04d-%02d-%02d`（metadata.py:63-65） |
| 标题 | 前 6 行里找首个含 `通知\|办法\|细则\|规定\|规则\|条件\|指引\|规程\|说明` 且长度 ≥8 的行（metadata.py:66-72） | 红头标题通常在前几行；"通知/办法/细则"是公文文种的强信号 |
| 城市/领域 | 前 600 字符里找 `_KNOWN_CITIES`（杭州/上海/北京/深圳/广州）与 `_DOMAIN_KEYWORDS`（公积金/社保/养老→社保/医保/医疗→医保）（metadata.py:48-50, 73-82） | 只在脏文档时兜底（`not content.startswith("【")` 守卫），规范文档尊重头部声明 |

测试锚点 tests/test_retrieval.py:74-92 用一段仿真红头公文验证：文号"杭房公委〔2023〕8号"、施行日期"2024-01-01"（"起实施"写法）、标题含"租赁提取政策"、城市杭州、领域公积金、无废止字样默认 `is_valid`。

### 2.4 规范化与防御（metadata.py:102-108）

- title 仍空 → 用文件名（metadata.py:102-103）；
- city 不在已知五城 → 空或"全国"归为"全国"，其他值原样保留（metadata.py:105-106）；domain 不在四域 → 归"通用"（metadata.py:107-108）。
- `date_rank`（metadata.py:112-117）：生效日期转 `date.toordinal()` 供新旧政策排序，非法日期返回 0——排序时沉底。

### 2.5 兜底抽取与下游的闭环

元数据三字段的消费点：**doc_no** 进生成上下文的引用行与 sources（nodes.py:241-244, 283-293）；**effective_date + is_valid** 进"现行有效/已废止"标注（nodes.py:242-243）；**city/domain** 进检索加权与路由（L1 §4）。所以扫描件管线修的不只是"能不能检索"，是"能否被正确加权、正确引用、正确标注时效"。

## 3. 常见错误实现对比

| 错误写法 | 后果 | 正确做法（源码位置） |
|---|---|---|
| pypdf 抽空就返回空字符串 | 空文本静默进索引，问题"看起来答了"其实无据 | 显式抛 ValueError 由上层跳过并记录（loader.py:26-34） |
| OCR 每次实时调用 | 重建索引/重跑测试都烧一遍视觉模型费用 | 内容哈希缓存（ocr.py:61-68） |
| OCR 缓存按文件名 | 文件被替换后读到旧转录 | `sha256(字节)[:16]` 进 key（ocr.py:65-66） |
| 单页失败放弃整份文档 | 一页噪声毁掉全文档 | 逐页 try，失败 warn 跳过（ocr.py:92-96） |
| 元数据只有规范头一级 | OCR 公文无城市/时效信号，加权失效 | 正文兜底抽取（metadata.py:53-82） |
| 施行日期只认"实施" | "起施行"写法的文件丢日期（时效排序错） | 两种写法都匹配（metadata.py:46-47） |
| 城市匹配扫全文 | 正文提到"参照上海做法"就误标城市 | 只扫前 600 字符头部（metadata.py:55, 73-77） |

## 4. 面试讲法

**30 秒版**：
> 真实政务 PDF 大量是红头扫描件——pypdf 实测 4 页只抽出 3 个字符。我做两级解析：页均字符密度低于 30 判为扫描件，降级 pymupdf 渲染+视觉模型逐页 OCR，结果按内容哈希缓存，mock 模式下无缓存就诚实抛错保证 CI 可离线。元数据也做两级：规范头正则之外，对无元数据头的 OCR 文本从正文兜底——文号匹配公文专用括号〔〕的正则，施行日期同时接受"起实施"和"起施行"两种写法，标题从前 6 行按文种关键词识别，城市/领域只扫前 600 字符防误伤。这些元数据直接喂给检索加权和答案里的时效标注。

**3 分钟版**：
- 第一分钟：讲 4 页 3 字符的发现过程与"静默空文本"的危害，两级解析的判定阈值（页均 30 字符）与两处显式抛错。
- 第二分钟：OCR 工程细节：逐页+单页失败跳过+内容哈希缓存+mock 诚实失败——每个决策对应一个真实故障场景。
- 第三分钟：元数据兜底的闭环：〔〕正则、实施/施行双写法（实测踩坑）、标题文种信号，然后讲消费端——文号进引用、时效进降权与标注、"现行有效"误标就是答错政策的根源。收尾：这是"摄取期锁死确定性"原则（metadata.py:6-8）的完整落地。

## 5. 自测五题（答案见文末折叠区）

1. `is_scanned_pdf` 为什么用"页均密度"而不是"总字符数"？`pages == 0` 为什么返回 False 而不是 True？
2. OCR 结果为什么按**内容**哈希缓存而不是文件名？`[:16]` 截断会不会碰撞风险过大？
3. `_DIRTY_EFFECTIVE` 正则里 `[自]` 和 `(?:实施|施行)` 各防什么漏抽？
4. 城市兜底为什么只看前 600 字符？举一个"扫全文会出错"的场景。
5. `extract_metadata` 里 `not content.startswith("【")` 这个守卫去掉会怎样？

<details>
<summary><strong>答案（先自己答再看）</strong></summary>

1. 总字符数会被页数干扰（长扫描件的总字符可能仍超过短文本件）；页均密度才刻画"每一页是不是图"。pages==0 返回 False：空 PDF 没有内容也没有页面，判为扫描件会触发一次注定失败的 OCR；按"非扫描件"返回空文本，走 loader 的空值抛错路径更合理（ocr.py:33-37）。
2. 文件名会变（重命名/重新下载），内容哈希才能表达"这份内容转录过没有"；文件被替换后哈希变化，旧缓存自然失效不误读。[:16] 十六进制 = 64 bit，语料量级（数百份）下生日碰撞概率约 n²/2^65，可忽略；截断换来短文件名（ocr.py:65-66）。
3. `[自]` 要求"自X年…"引导词，防把"2024年1月1日发布"之类的日期误当施行日（发布≠施行）；`(?:实施|施行)` 是**两种公文写法**都接受——源码注释明确"实测真实文件两种都在用"（metadata.py:46-47），只认一种会漏掉整类文件。
4. 公文正文常引用外地文件："参照《上海市…办法》""学习北京经验"。扫全文会把 city 误标成第一个出现的城市名，检索加权（×1.8/×0.5）随之把文档推向错误子空间。头部 600 字符基本覆盖发文机关与标题，正文引用进不来（metadata.py:55, 73-77）。
5. 规范头文档的正文里也含"杭州""公积金"等词——去掉守卫后，兜底逻辑可能在头部已声明【适用城市】上海时，又被正文的"杭州"字样覆盖/冲突；守卫保证两级抽取互斥：有头按头，无头才兜底（metadata.py:100-101）。
</details>
