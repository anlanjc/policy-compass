## 第一步：按依赖顺序通读（2h，读法见各文件卡片）

**阅读顺序 = 依赖顺序**，每读完一个文件做一次"合卷复述"：它能干什么、为什么这么写、面试会问什么。

### 📄 `app/agent/graph.py`（先读！看图长什么样）
- **干什么**：LangGraph StateGraph 的节点注册、四条边、两个条件边函数 `_after_grade` / `_after_verify`
- **为什么**：条件边是纯函数（只读 state 里的分数与计数），不 import 模型——"编排与推理分离"
- **面试考点**：画完整状态转移图；`recursion_limit` 与 `max_query_rewrites` 为什么双重保险；thread_id/checkpointer 的作用
- **自测**：改写循环第二轮检索仍不相关时，走哪条边退出？

### 📄 `app/agent/nodes.py`（图的血肉，最长也最重要）
- **干什么**：8 个节点工厂（闭包注入 retriever/llm）；`build_generation_messages` 被图内生成与 API 流式**共用**——行为一致的关键
- **考点**：grade 并行+单条超时+保守分 0.3 的降级链；verify 的 prompt 为什么明确豁免程序性话术（生成/校验对齐）；trace 事件 `_ev()` 如何既推 SSE 又落 JSONL
- **自测**：`grade_node` 里 gather 挂了 3 个成功 2 个超时会怎样？（答：超时的记 0.3，不整体失败）

### 📄 `app/retrieval/hybrid.py` + `bm25.py`（检索核心）
- **干什么**：双路并行 → RRF → 三级业务加权 → rerank 降级；Okapi BM25 逐行实现
- **考点**：BM25 公式默写（idf 饱和、k1、b 各管什么）；`tokenize()` 为什么有 bigram 通道（分词粒度失配踩坑）；RRF 的 k=60 什么含义（排名平滑）；为什么加权在 RRF 之后（融合序上加权，避免原始分数量纲干扰）
- **自测**：黑话扩展词为什么是 0.6 权重不是 1.0？

### 📄 `app/llm/client.py` + `mock.py`
- **干什么**：手写 OpenAI 兼容协议；`chat_json` 自校验纠错循环（解析失败→错误回灌重试）；mock 继承真实类只覆写网络层
- **考点**：哪些错误可重试（429/5xx/网络）、哪些不重试（4xx 统一包装 LLMError）；为什么 mock 不绕过 chat_json（替身走真实调用路径原则）
- **自测**：流式 SSE 帧格式是什么？`[DONE]` 谁发的？

### 📄 `app/ingestion/`（indexer → splitter → metadata → ocr）
- **考点**：条文感知切分为什么按"第X条"聚合；增量同步的 hash 机制；扫描件判定阈值（页均 30 字符）与 OCR 哈希缓存；脏文本元数据兜底正则
- **自测**：政策修订后旧文件为什么保留（降权可答"新旧差异"）而不是物理删除？

### 📄 `app/api/routes.py` + `main.py`
- **考点**：双入口（非流式走图/流式图外接管）为什么行为能一致（同一组节点函数）；SSE 三类帧（meta/trace/token/done/error）；lifespan 里组件装配顺序

## 第三步：亲手做增量实验（2h，产生"完全属于你"的数字）

三选二做完，每个都有"假设→改动→数字"闭环，面试讲起来底气完全不同：

1. **chunk_size 扫参**：`.env` 里 `CHUNK_SIZE=300/450/800` 各跑一遍 `python scripts/eval.py`，对比 recall@5 与 MRR，写 3 行结论进 eval_report
2. **加一个城市**：仿照语料头格式写 1 篇（真实或标注演示），`RENT_LIMITS` 加一行，评测集加 2 题，重跑评测
3. **加一个工具**：如"公积金账户利息测算"，抄 `rent_extract_limit` 的三件套（纯函数 + TOOL_SCHEMAS 条目 + 测试）

## 第四步：面试题库与情景演练（1.5h）

### 4.1 高频八股 → 项目锚点（每题先答概念再落到项目）

| 八股题 | 项目锚点 |
|---|---|
| RAG 完整链路/检索不准怎么优化 | 我的双路+加权+改写循环；排查顺序：分词→加权→embedding |
| ReAct vs Plan-and-Execute | 本项目是 CRAG 变体：检索-评估-修正循环，不是开放式规划 |
| Function Calling 流程 | schema 注入→抽参→防御转换→执行→结果回填→verify 参与 |
| SSE vs WebSocket | 单向推送够了；HTTP 语义、自动重连、代理友好；双工才需要 WS |
| 幻觉怎么缓解 | 三层：生成 prompt 硬约束 / verify 逐句溯源 / 拒答分支兜底 |
| 多轮上下文/成本 | history_window 截断 + 按题型配模型档位（评分校验可用小模型） |

### 4.2 深挖追问树（面试官的三层追问，逐层备好）

**"你的混合检索怎么做的？"**
├─ L1：BM25 和向量各召回多少？（top_k_recall=20，RRF 融合后 top_k_final=5）
├─ L2：为什么 RRF 不用加权分数融合？（量纲不可比；rank 天然归一）
└─ L3：加权系数 1.8/1.3/1.6 怎么定的？（业务约束推导+消融验证；诚实说：网格粗调，不是精细优化）

**"agent 怎么体现的？"**
├─ L1：判定标准——检索是否成为可决策/可重试/可放弃的动作
├─ L2：条件边为什么看分数不看模型？（量化信号可测试、可回归）
└─ L3：agent 失控怎么办？（循环上限+recursion_limit+拒答分支，三层刹车）

**"评测怎么做的？"**
├─ L1：33 题六类，每题带期望文档/关键词/工具数字
├─ L2：检索指标为什么用规则路由？（隔离 LLM 变量）
└─ L3：93.9% 怎么算的？（按题型判分：拒答看 refusal、计算看工具数字、其余看关键词+引用；2 例误拒是主要损失）

### 4.3 情景题（用项目的真实经历答）

- **"上生产你要补什么？"** → 鉴权限流、缓存层、评分/校验换小模型、Langfuse 替换自研 trace、语料整体替换为官方文本 + 更新机制
- **"检索结果和模型知识冲突怎么办？"** → 政策场景的结构性防御：答案只允许来自上下文（prompt 硬约束+verify+拒答），模型参数知识永远不是来源
- **"你这个项目 AI 参与了多少？"** → 坦诚模板："架构、决策和全部调优是我做的，AI 辅助编码提速；任何一个模块我可以现在讲、现场改"（然后真的能——这就是前三步的意义）

## 关于"证明是自己做的"——只做真实的事

**不做**：不伪造手写记录、不重写 git 历史造假、不背"我一周没睡做出的"这种经不起一句追问的剧本。面试官识别"真做过"的方式是三层追问，任何表演都扛不住第三层。

**做（全部真实且更有效）**：
1. **让 git 历史自然延续**：第三步的实验用你自己的账号提交——从今天起的 commit 都是你的，项目从"AI 起步"变成"你持续演进的真实项目"
2. **自己跑一遍评测**（半小时）：`cp .env.example .env`→填 key→`python scripts/eval.py`。之后简历上每个数字你都能说"我跑的"
3. **写一篇踩坑博客**（掘金/CSDN，2h）：挑三个故事（bigram、传参防御、OCR 管线）写成"问题→定位→方案"——发布链接放简历，这是最强的归属证明，还顺手完成了路线图里的"笔记写成博客"任务
4. **模拟面试**：让任何人（或 AI 扮演面试官）按 4.2 的追问树打你三轮，答不上第三层的回去补

> 判断自己是否内化完成的标准：**把电脑合上，你能把 PROJECT_BOOK.md 第 5 节（一次问答的生命周期）和第 8 节（六个踩坑）用自己的话讲满 5 分钟，中间不卡壳。** 达到了，这个项目就是你的。
