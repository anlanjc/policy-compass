# 向量腿消融报告：BM25-only vs 混合检索（2026-11-05/06，S1）

> 评测集=冻结口径（v1 33 题 smoke / v2 90 题分层，检索指标 n=78 题含目标文档集，refuse 题不参与）。
> chat 全程 `POLICY_COMPASS_FORCE_MOCK=1`（判分确定性、零 chat 花费）；**向量腿是唯一真变量**（DashScope text-embedding-v4，1024 维）。
> 原始数据：`evidence/ablation_bm25.json` / `ablation_embed.json` / `ablation_hybrid.json` / `ablation_restore_mock.json`；脚本 `scripts/ablation_vector.py`（三阶段+恢复口径，app/ 零改动）。

## 0. 结论先行

1. **向量腿贡献（检索层，确定性指标）**（hybrid_full vs 生产 BM25+加权）：recall@5 **v2 +0.9pp**（97.2→98.1）/ v1 **-1.1pp**（96.5→95.4，n=29 小样本负贡献）；**MRR 双集上涨**（v2 0.949→0.984、v1 0.831→0.902）——正确文档几乎恒定 Top1；废止泄漏全配置 **0** 持平。
2. **端到端：mock 与 real 方向相反，最终结论=保留架构与开关、生产默认维持关闭（BM25-only）**。mock 判分器下 e2e +2.2pp/+3.0pp（91.1→93.3 / 84.9→87.9）；但**真模型全量复验（2026-11-06，主人批准）证伪了这一外推**：v2 92.2%（vs 冻结 BM25-only 93.3%，-1 题）/ v1 93.9%（vs 冻结 100%，-2 题），3 条差异全部是 `refusal=True` 的**评分抖动误拒**（保守方向、零编造），落在 PC-3 已记录的抖动噪声带内（同类误拒在冻结口径历史运行中本就 93.9%↔100% 摆动）。**排序增益（MRR）真实存在但未传导到真模型端到端**——真实模型对 rank2~3 的差异鲁棒，mock 的抽式判分（只读 top1）才会被重排放大。切换的收益证据不足，而成本（延迟 +0.3s/检索、CI 门禁基线重建、冻结口径更新）确定。
3. **诚实反转一笔**：v2 上 hybrid_no_boost（98.7%）> hybrid_full（98.1%）——向量路开启时业务加权有轻微抢占，与 PC-2"加权不再有 recall 增益"的诚实翻转方向一致；加权保留价值仍是废止零泄漏与跨城召回结构，不在 ±1pp 噪声量级上调参（holdout 纪律同理）。
4. **方法论收获（面试可讲）**：这次消融的价值恰在于让"要不要开向量"由数据而非直觉决定——两层结论（确定性检索指标可跨判分器复用；mock e2e 增益不可外推到 real）都是"分层评测 + 双口径纪律"逼出来的。

## 1. 结果总表

**v1 smoke（n=29）**

|---|---|---|---|---|
| BM25 纯净 | 98.3% | 0.833 | 0 | — |

e2e 失败集变化：v2 由 8 条（#105/129/131/167/**177**/179/183/**189**）减至 6 条（#177/#189 被向量腿救回）；v1 由 5 条减至 4 条（#22 救回）。v2 hybrid e2e 93.3% 与 real 冻结口径 93.3% 同值属巧合（判分器不同，不构成互证）。

**延迟代价**：混合 e2e P50 278~328ms vs 纯 BM25 ~24ms——每检索一次 +~0.3s（查询向量网络调用，单条一批）。生产 real 口径 P50 ≈15s（每问 8~9 次 LLM 调用），向量腿占比 <2%；mock 口径下放大 10 倍但绝对值不变。

## 2. 实验设置

- **配置组**（5 组）：bm25_only（纯净）/ bm25_production（生产加权、向量关）/ vector_only / hybrid_no_boost / hybrid_full（生产加权+向量，`vector_weight=0.8`，config.py:66）。前四组加权系数经"捕获-置 1.0-还原"隔离（eval/runner.py:95 `ablation` 同款机制）。
- **真实向量注入**：`--phase embed` 原地 UPDATE chunks.embedding（输入逐字复刻 `_ingest` 的 `f"{c.title}\n{c.text}"`——注意 `splitter._pack` 从不赋值 Chunk.title，**生产 embed 输入实为 `"\n"+正文`**，标题经正文首行《标题》进入；本 quirk 已报主人，修复会动全部 chunk 向量故不擅改）。68 chunk、30,852 字符、7 次调用（DashScope 批量上限 10）、11.1s、维度 1024 与配置一致。
- **混合腿**：`--phase hybrid` 进程内把 `app.llm.client.get_llm` 替换为"真 embed + mock chat"组合客户端（`RealEmbedMockChat`），chat 判分口径与冻结 mock 完全一致；查询向量逐条真实调用。app/ 源码零改动，闸门=必须存在 embed 产物（哈希向量同样非零，非零计数区分不了真假）。
- **恢复口径**：`--phase restore_mock` 用 MockLLMClient.embed（md5 词袋哈希、无随机无网络）把库向量恢复为 FORCE_MOCK 哈希口径——恢复后 `eval.py` 复现 v1 84.9%/v2 91.1% **逐字一致**，冻结 mock 数字复现性不受实验影响。

## 3. 口径关系：与 agenteval CI 门禁基线（重要，勿混写）

**"BM25-only"在本项目里有三个不同口径**，本报告把它们拆开：

| 口径 | 环境 | 查询向量腿 | recall@5 (v2) |
|---|---|---|---|
| A. 生产 BM25-only | 无 FORCE_MOCK + `EMBED_ENABLED=false` | 真实客户端落零向量→腿真空转（client.py:238） | 97.2%（加权） |
| B. FORCE_MOCK 现行 | `POLICY_COMPASS_FORCE_MOCK=1`（**CI 门禁/e2e mock 同环境**） | **MockLLMClient.embed 不检查 embed_enabled→哈希词面向量腿实际在跑**（mock.py:79） | 93.8% |
| C. 混合（真向量） | FORCE_MOCK + 真实 embed 客户端 | 真实 text-embedding-v4 | 98.1% |

- **发现**：mock 哈希向量腿在 FORCE_MOCK 环境下**拖低** recall@5 约 3.4pp（93.8 vs 97.2）——mock 口径的端到端数字（91.1%）一直是"BM25+加权+哈希向量腿"的混合体，README「mock 模式下向量路退化为词面匹配」声明对应此状态。
- **与门禁的关系**：agenteval 30 条 policy smoke 基线是在 B 口径下构建的快照，**自洽**（基线与被测同环境）；门禁守护的是"相对基线无回归"，不是"绝对检索质量"。本消融的 A/B/C 拆分不改变门禁语义。
- **若生产切 hybrid**（主人决策项）：门禁基线**必须重建**——现基线锚在 B 口径，服务端切到真向量后 smoke 输出全体漂移。重建须逐条判读失配原因，把"重建"与"放水"区分开（PC-3 预演教训：push 前本地预演门禁）。CI 环境（零 key）无法跑真向量，届时门禁需注入 embed key 或改锚 A 口径指标——这也是"暂缓切换"的现实理由之一。

## 4. 真模型复验（2026-11-06，主人批准，本报告的终审环节）

真模型（deepseek-v4-flash-0731，与冻结口径同模型同金标）下全量 e2e 对比，混合腿=真实向量入库+`EMBED_ENABLED=true`：

| 评测集 | BM25-only（冻结 real 口径） | 混合真向量（本轮） | Δ | 失败归因 |
|---|---|---|---|---|
| v2 full（90 题） | 93.3%（84/90） | **92.2%**（83/90） | -1 题 | 6→7 条失败：新增 1 条 `refusal=True` 评分抖动误拒（#116/#175 同类；#144 冻结口径本就拒答）；#113/#114 等金标写法变体两轮同败 |
| v1 smoke（33 题） | 100%（33/33） | **93.9%**（31/33） | -2 题 | #32/#23 均 `refusal=True` 误拒——与冻结口径"历史 2 例评分抖动误拒"同类（该类在 PC-2→PC-3 同代码运行中本就 93.9%↔100% 摆动） |

- **方向与 mock 相反**（mock +2.2/+3.0pp → real -1.1/-6.1pp）；差异全部为保守方向误拒、**零编造**（refuse 子集 12/12、4/4 全过），落在 PC-3 记录的评分抖动噪声带（±1~2 题）内，无一条可归因于检索缺料（v2 hybrid recall@5 98.1% ≥ BM25 97.2%）。
- **机理**：真实模型对 top1~top3 的排序差异鲁棒（都能读到正确条文），MRR 增益不传导到答案；mock 是抽取式判分（只读 top1），重排增益才被放大——**mock e2e 是链路回归裁判，不是增益外推依据**。
- P50 延迟：v2 19.2s / v1 24.8s（vs 冻结 BM25-only 15.0/20.1s，含网络查询向量 +~0.3s/检索与运行间抖动）。
- usage：v2 588,693 in + 165,651 out；v1 235,496 in + 72,972 out——按 PC-3 同款估价（in ¥0.5~2/M、out ¥2~8/M）**≈¥0.9~3.6（上限 ¥5，未超）**，账单以百炼为准。报告：`evidence/eval_v2_real_hybrid.md` / `eval_v1_real_hybrid.md`（内含同口径四组检索消融表，与 hybrid 阶段独立复跑逐格一致）。

## 6. 诚实边界

- **单 embedding 模型单次采样**：结论仅对 text-embedding-v4（1024 维）成立；bge-m3（config 默认）或更高维模型结论可能不同。n=78/29 小样本，±1pp 内差异不作结论（v1 的 -1.1pp 落在 2 题翻转量级）。
- **真模型复验同样是单次采样**：-1/-2 题的差异归因于评分抖动（有 refusal=True 证据链），但理论上不排除"混合腿偶然多触发一次误拒"的巧合；若要更硬的结论可做 N 次重复运行（成本 ≈¥1~2/轮），当前证据已足够支持"维持 BM25-only"的默认决策。
- **评分抖动是本项目真模型口径的主要残差**（PC-3 起记录在案）：同代码同金标下 v1 real 在 93.9%↔100% 间摆动；任何 ±2 题内的 e2e 对比都应先看失败是否为 `refusal=True` 误拒类。
- **加权与向量路的交互未调优**：hybrid_no_boost 优于 hybrid_full 提示存在联合调参空间，但按纪律不在 mock 噪声量级上调参。
- **实验期间库向量多次换装**（哈希→真→哈希→真→哈希），每次终态均恢复冻结兼容口径并逐字验证（84.9%/91.1%）；`ablation_restore_mock.json` 留痕。
