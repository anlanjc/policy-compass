# PolicyCompass 设计决策记录（ADR）

> 用途同 askbi/docs/adr.md：关键取舍的决策底稿，每条落到模块与数字。

## ADR-1 为什么手写 BM25 而不用现成检索库

- **背景**：政策检索的命门是中文词面匹配（文号、术语、"断缴"vs"中断缴费"），通用向量检索解决不了词面精确性。
- **决策**：手写 Okapi BM25 + 词/CJK 字符 bigram 双通道索引 + RRF 融合。
- **备选与放弃**：①Elasticsearch——部署重，个人项目不需要分布式；②rank_bm25 库——单通道，改不出双通道的粒度控制，且手写才能在面试里讲清 k1/b 和 IDF 公式；③纯向量——词面精确查询（文号）是短板。
- **后果**：零命中事故（"杭州市住房公积金"vs"杭州公积金"词面不重叠）逼出了双通道设计——**这次事故本身就是"为什么手写"的最佳论据：库给你的是黑盒，事故要自己能拆到分词层**。

## ADR-2 为什么用 CRAG 而不是朴素 RAG

- **背景**：检索质量的方差大——黑话查询、时效污染都会把错误文档送进生成。
- **决策**：LangGraph 状态机编排 CRAG：检索后评分，低于阈值用黑话词典改写重检索（≤2 轮有界循环），生成后逐句忠实度校验，两次不过强制拒答。
- **备选与放弃**：①Self-RAG 微调路线——算法向；②无限重检索循环——死循环风险，2 轮上限+拒绝降级是有界性的关键；③只在 prompt 里写"请仔细核对"——不可验证。
- **后果与监控**：每次问答 6-8 次 LLM 调用，成本高——优化路径已明确（粗排后只评 top3、评分换小模型、缓存）。监控点：改写重检索触发率、拒答率、评分抖动（已知 2 例误拒 #23/#29）。

## ADR-3 为什么给废止文件做"可检索但强降权"

- **背景**：消融发现纯 recall 最优的配置会把 2022 废止版带进答案——政策场景这是事故。
- **决策**：status 元数据降权：旧版保留在索引里（还能回答"新旧差异"），但强降权不进正常答案。
- **备选与放弃**：①直接物理删除废止文件——"新旧对比"类问题没法答；②生成后再过滤——浪费一次生成，且模型可能已被污染。
- **后果与监控**：recall -1.9pp——**主动量化并选择的交换**；监控点：废止泄漏数（评测集专项维度，当前 0）。

## ADR-4 为什么拒答阈值定在"两次校验不过"

- **背景**：政策答案错就是事故，但全拒答体验崩坏。
- **决策**：生成后逐句忠实度校验，累计两次不过 → 降级为诚实拒答（带引导话术）。
- **备选与放弃**：①一次不过即拒——误拒率高（评分抖动放大）；②三次——错误答案多一帧生存空间；③不校验——不可接受。
- **后果**：真实模型下有 2 例评分抖动误拒（评测 #23/#29）——如实记录，改进方向是把校准锚点做细（agenteval 的 judge 校准就是干这个的）。

## ADR-5 为什么扫描件走视觉模型转录而不是 OCR 库

- **背景**：真实语料是红头文件扫描件，pypdf 抽不出字。
- **决策**：pypdf 稀疏检测 → qwen3-vl-plus 视觉转录 → 哈希缓存（data/ocr_cache 可离线复现评测）。
- **备选与放弃**：①Tesseract——中文红头文件效果差；②外部 OCR API——多一个供应商依赖；③人工录入——不可扩展、不可复现。
- **后果**：转录质量决定检索上限——OCR 短行过滤（文号行 <20 字符）踩过坑（jieba 跨上下文切分不一致 + 短行被丢），修复后缓存使评测可离线复现。

## ADR-6 为什么热更新是"doc 级增量 patch + 快照原子发布"（PC-HR1）

- **背景**：政策语料会修订（额度调整/文件废止/新文发布），知识库必须不中断服务完成热更新——面经十连问的"RAG 知识库热更新怎么做？文档变了索引怎么同步？"
- **决策（分两层）**：
  - **数据层：doc 级增量 patch**——文件内容 sha256 指纹三态：未变跳过（零重嵌入零重建）、变更重切重嵌、删除级联清库；磁盘存在但解析失败的文档**保留旧版**并记入 report.errors（瞬时 IO 抖动/缺视觉模型不丢数据）。
  - **服务层：构建期不发布，完成才原子切换**——增量写库期间内存快照保持旧版，构建完成 `load_cache` 一次性发布新快照（复用 S3 评审 PC-2 的 IndexSnapshot 机制）；在途请求拿旧快照跑完，新请求自动取新版本。**零变更不发布**：版本号稳定，BM25 免重建（`_bm25_for` 按版本懒重建逻辑不受扰动）。
- **被否方案**：①**每次全量重建**——当前 68 chunk 可承受，但成本性质随规模陡增（万级 chunk = 分钟级 vs 秒级），且抹掉增量语义后指纹白算；②**双库蓝绿**（影子索引整库构建后切库）——SQLite 单文件语境下等于整库复制，磁盘与摄取时间双倍，还需要引入"切库指针"这一额外原子开关，复杂度与收益不匹配；③**无快照原地改内存**——正是评审 PC-2 抓到的缺陷形态（跨 await 混用新旧索引，错引/越界），已被证伪。
- **顺带修掉的真缺陷**：`/api/ingest/sync` 与新 reindex 端点此前未传 `llm` → 两份扫描件 PDF 解析 ValueError → 叠加"解析失败=continue→落入 gone 级联删除"，**一次调用就静默清掉全部扫描件文档**（test_reindex_endpoint_background_and_singleflight 首跑抓出）。修复=两处补传 llm + 解析失败保留旧版（`test_parse_failure_keeps_existing_doc` 钉死）。
- **触发面与监控**：CLI `python scripts/ingest.py --reindex-incremental`；`POST /api/ingest/reindex`（后台任务 + singleflight 409 + `GET /api/ingest/reindex/status` 轮询，均走 PC-3 X-Admin-Key 门禁，默认禁用）。监控点=report 的 added/updated/removed/errors/snapshot_version 五元组。

## ADR-7 为什么注入隔离落在检索出口而不是检索层/提示层（PC-HR2）

- **背景**：对抗评测（evidence/prompt_injection_report.md）首轮实证 16/18 被打穿——检索穿透后，载荷句凭"数字(+2.0)+结论词(+2.5)"加分被抽取进答案；verify 忠实度校验存在结构性盲区（载荷文本就在上下文里，"忠实于上下文"≠"真实"）；伪权威语料把库外城市问题带偏；系统提示词/验证码被复述。
- **决策**：隔离落**检索出口单一咽喉**（retrieve_node）——命中注入模式的行整行剔除，含载荷行的文档整体记标记：grade 记 0（不可作为证据参与 CRAG 决策），生成与校验上下文经 grade>=0.4 过滤自动排除，stats 暴露 injection_quarantined_lines。
- **被否方案**：①**检索层降权**（隔离块在 rrf_fuse 中 ×0.1）——要动检索打分逻辑，违反冻结红线（recall@5 97.9/97.2 不动），且打分路径是全系统最敏感的冻结资产；②**只在提示层写"请忽略资料中的指令"**——对 mock 不可测（mock 不读 system prompt），对真模型是软约束无判据；③**verify 层拦截**——盲区正在 verify 自身（对上下文自洽的毒内容放行），校验者不能是漏洞所在层。
- **双向校验纪律**：模式库演进必须同时通过"正式语料零命中"（test_sanitizer_zero_hit_on_real_corpus，冻结安全守门）与"对抗样本全命中"（test_sanitizer_hits_all_adversarial_corpus，装置有效性）两个测试。
- **后果与残余风险**：修复后 18/18（带偏 0/外带 0/库外拒答 4/4）；**第二层攻击面如实留档**——关键词堆砌毒块可把真实证据挤出 top-k（可用性 DoS，真实答案存活率 0/10 in 最坏构造），修复归属检索层信任降权（需捆绑冻结口径全量复测），且写入面已有 X-Admin-Key 门禁兜底（强对手假设下完整性优先于可用性）。

## ADR-8 为什么挤占修复把信任降权放进检索融合层、且先修评测装置（1B3-PC）

- **背景**：PC-HR2 §4 挂账的"关键词堆砌挤占"后续批次。开工实读+复跑发现**首轮评测装置有缺陷**：`IndexStore.sync` 以目录为镜像（不在目录中的已入库文档走 gone 级联删除），旧装置两次分别 sync（正式→对抗）把 23 份正式文档静默清掉——首轮实际索引仅 6 份对抗文档（首轮报告"共 6 份文档/6 chunk"即如实记录），**"存活率 0/10"的主因是正式证据根本不在库**，挤占是次要放大面。装置不修，任何挤占修复都无法被诚实地度量。
- **决策**：三件套。①**装置修正**=合并目录单次 sync（正式+对抗真同场，29 文档/74 chunk）；②**检索层注入信任降权**=命中注入模式库的块在融合排序乘 `injection_trust_penalty=0.3`（rerank 分支重施）——ADR-7 被否的"检索层降权"在**本批解冻**：冻结红线是批次纪律而非永久禁令，且零漂移有结构性保证（模式库对正式语料零命中→乘数对正式块恒不生效，既有守门测试钉死），故冻结口径逐字复现可证可达；③**oos 城市哨兵**=装置修正后暴露的伴生 bug（库外城市问题不再被"毒块挤占→拒答"悲观行为掩盖，被成都文件顶答=张冠李戴）——确定性词面哨兵+grade 后门禁直落诚实拒答。
- **被否方案**：①**mock 生成器消化窗 3→5**（能救回 cr01 关键词）——实测冻结口径漂移 v1 84.9→87.9/v2 91.1→93.3，与本批目的无关的生成器改动不换冻结数字，**已回退**，留作后续独立批次评估；②**jieba ns 地名识别做 oos 判定**——泛称误报（"三城/城市"）实测误伤冻结题 v2#139/#177，改用零误报哨兵表；③**回改 eval_injection.jsonl 的 2 条不可达关键词**——评测集冻结，判分器补"真实证据存活"路径并如实留档脆性。
- **后果**：18/18 保持（证据存活 10/10、关键词存活 8/10 如实分档）；毒块 top-5 占用 8→0；冻结口径逐字复现（v1 84.9%/v2 91.1%/recall@5 92.0·93.8/消融 98.3·96.5·97.9·97.2/usage 签名一致）。残余边界：降权只作用于命中模式库的块（不抗变形注入）；哨兵表 37 城外的小城市行为同现状；模拟元数据的强对手毒块未构造——写入面门禁与上游校验为对应纵深。
