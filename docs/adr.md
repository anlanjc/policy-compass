# PolicyCompass 设计决策记录（ADR）

> 用途同 askbi/docs/adr.md：关键取舍的决策底稿，每条落到模块与数字。

## ADR-1 为什么手写 BM25 而不用现成检索库

- **背景**：政策检索的命门是中文词面匹配（文号、术语、"断缴"vs"中断缴费"），通用向量检索解决不了词面精确性。
- **决策**：手写 Okapi BM25 + 词/CJK 字符 bigram 双通道索引 + RRF 融合。
- **备选与放弃**：①Elasticsearch——部署重，个人项目不需要分布式；②rank_bm25 库——单通道，改不出双通道的粒度控制，且手写才能在面试里讲清 k1/b 和 IDF 公式；③纯向量——词面精确查询（文号）是短板。
- **后果**：零命中事故（"杭州市住房公积金"vs"杭州公积金"词面不重叠）逼出了双通道设计——**这次事故本身就是"为什么手写"的最佳论据：库给你的是黑盒，事故要自己能拆到分词层**。

## ADR-2 为什么用 CRAG 而不是朴素 RAG

- **背景**：检索质量的方差大——黑话查询、时效污染都会把错误文档送进生成。
- **决策**：LangGraph 状态机编排 CRAG：检索后评分，低于阈值用黑话词典改写重检索（≤2 轮有界循环），生成后逐句忠实度校验，两次不过强制拒答。
- **备选与放弃**：①Self-RAG 微调路线——算法向；②无限重检索循环——死循环风险，2 轮上限+拒绝降级是有界性的关键；③只在 prompt 里写"请仔细核对"——不可验证。
- **后果与监控**：每次问答 6-8 次 LLM 调用，成本高——优化路径已明确（粗排后只评 top3、评分换小模型、缓存）。监控点：改写重检索触发率、拒答率、评分抖动（已知 2 例误拒 #23/#29）。

## ADR-3 为什么给废止文件做"可检索但强降权"

- **背景**：消融发现纯 recall 最优的配置会把 2022 废止版带进答案——政策场景这是事故。
- **决策**：status 元数据降权：旧版保留在索引里（还能回答"新旧差异"），但强降权不进正常答案。
- **备选与放弃**：①直接物理删除废止文件——"新旧对比"类问题没法答；②生成后再过滤——浪费一次生成，且模型可能已被污染。
- **后果与监控**：recall -1.9pp——**主动量化并选择的交换**；监控点：废止泄漏数（评测集专项维度，当前 0）。

## ADR-4 为什么拒答阈值定在"两次校验不过"

- **背景**：政策答案错就是事故，但全拒答体验崩坏。
- **决策**：生成后逐句忠实度校验，累计两次不过 → 降级为诚实拒答（带引导话术）。
- **备选与放弃**：①一次不过即拒——误拒率高（评分抖动放大）；②三次——错误答案多一帧生存空间；③不校验——不可接受。
- **后果**：真实模型下有 2 例评分抖动误拒（评测 #23/#29）——如实记录，改进方向是把校准锚点做细（agenteval 的 judge 校准就是干这个的）。

## ADR-5 为什么扫描件走视觉模型转录而不是 OCR 库

- **背景**：真实语料是红头文件扫描件，pypdf 抽不出字。
- **决策**：pypdf 稀疏检测 → qwen3-vl-plus 视觉转录 → 哈希缓存（data/ocr_cache 可离线复现评测）。
- **备选与放弃**：①Tesseract——中文红头文件效果差；②外部 OCR API——多一个供应商依赖；③人工录入——不可扩展、不可复现。
- **后果**：转录质量决定检索上限——OCR 短行过滤（文号行 <20 字符）踩过坑（jieba 跨上下文切分不一致 + 短行被丢），修复后缓存使评测可离线复现。
